# プロジェクト開始時の設計（仮置き）

## 目的

JRA平地競走について、レース前に入手できる情報だけから各出走馬の勝率を推定し、将来期間で再現可能に検証する。

## 最初に固定する境界

- 対象: JRAの平地競走。障害競走、地方競馬、海外競馬は初期対象外。
- 予測時点: 発走時刻より前。各特徴量には取得時刻または有効時点を持たせる。
- 予測対象: 出走馬ごとの勝率。レース内の確率合計は1とする。
- 主評価: レース単位のLog Loss。予測精度と確率校正を同時に見るため。
- 副評価: 単勝回収率。控除率の影響があるため、精度指標とは分けて扱う。
- 分割: 日付順のwalk-forward。ランダム分割は未来情報の混入を招くため使わない。
- ベースライン: レース内一様確率と、入手時点を固定した単勝オッズ由来確率。

## データの流れ

1. `data/raw/`: 取得原本、取得日時、出典、利用条件を保存する。原本は更新しない。
2. `data/processed/`: 原本から決定的に再生成できる正規化データと特徴量を置く。
3. `src/`: 取得、整形、特徴量、学習、評価のコードを置く。
4. `tests/`: データ契約、時点整合性、分割、指標の検証を置く。
5. `docs/`: 判断理由、失敗、再現手順を残す。
6. `outputs/`: 利用者向けの表・グラフ・モデルカードだけを置く。
7. `work/`: 調査途中の一時ファイルを置く。

## 完了条件

同じ入力原本から同じ加工データを再生成でき、各レースの予測確率合計が1で、学習期間より後の検証期間に対してベースラインと候補モデルのLog Lossを同一レース集合で比較できる。回収率を出す場合は、購入判断に利用したオッズの観測時点を明記する。

## 次の着手

データ取得先ごとに、取得可能項目、時点、利用条件、費用、再現性を公式情報から確認し、採用する入力経路を1本に絞る。取得を始める前に最小スキーマとデータ契約を確定する。
