# データ取得経路の採用判断

確認日: 2026-09-23

## 結論

入力経路は **JRA-VAN Data Lab. の JV-Link / JV-Data** に一本化する。契約とデータ取得は課金を伴うためまだ実行しない。契約前でも、公開されている公式仕様に基づくスキーマ設計と取込コードの境界設計までは進める。

## 判断理由

- JRA-VAN Data Lab. はJRA公式データの配信サービスで、JV-Linkが通常・今週分・セットアップデータの取得を担う。画面HTMLではなく、仕様書でレコード形式と提供時点が定義されている。
- 速報レース情報 `0B15` は出走馬名表時点・出馬表時点から提供され、速報オッズ `0B31` と時系列オッズ `0B41` は発売開始後に提供される。馬体重 `0B11` は発走約1時間前であるため、予測時点より前に観測できた情報を区別できる。
- 時系列オッズ `0B41` は複数時間帯をレース単位で取得でき、提供期間は1年間と明記されている。確定オッズを過去時点の予測へ混ぜる事故を避けやすい。
- 月額2,090円（税込）であり、登録・課金は利用者確認が必要な不可逆工程として切り離せる。
- 利用規約上、取得情報は本人の私的利用が原則である。このプロジェクトの原本と個票は非公開とし、外部公開を行う場合は集計結果を含めて権利条件を別途確認する。

## 捨てた経路

JRA公式ホームページのHTML取得は採用しない。閲覧には向くが、ページ内容は予告なく更新・変更・削除され得るうえ、機械取得用の安定したレコード仕様と提供時点の契約を確認できなかった。再現可能な時系列検証という目的に対して、HTML構造の追随と観測時点の復元が余計な不確実性になる。

第三者配布CSVや非公式スクレイピングデータも採用しない。出典、補正履歴、観測時点、再配布権限のいずれかを独立に検証できない場合、指標が良くても再現と公開判断に使えないためである。

## 実装上の制約

1. 予測締切は発走予定時刻の10分前とする。
2. 特徴量に使えるのは `available_at <= prediction_cutoff` の版だけとする。
3. 速報開催情報は取り消しがあり得るため、取得のたびに前回状態を破棄するという公式仕様に従う。一方、監査用原本は取得時刻別に追記保存する。
4. 学習用の結果は予測入力と別テーブルに置き、特徴量生成処理から列名でも参照できないようにする。
5. 速報・時系列データには提供期間があるため、初回取得で過去全期間を復元できると仮定しない。

## 次に再現する手順

1. 利用者が契約実行を明示した後に、Data Lab.利用登録とJV-Linkの導入を行う。
2. SDK付属の検証ツールで `RACE`、`0B15`、`0B11`、`0B41` を各1レース取得できることを確認する。
3. 同じ指定を自作取込処理で読み、レコード件数と主キー集合が検証ツール側と一致することを確認する。
4. 原本を取得時刻別に保存してから、`docs/02_data_contract.md` の4テーブルへ正規化する。
