# 初期構成

## 目的

携帯とPCのどちらからでも指示・確認でき、PC停止中も実装・調査・監視が継続できるようにする。

この基盤が扱う題材は次の3領域とする。

1. 個人的に利用するアプリの開発と改善。
2. 競馬のデータ分析。
3. 実現できるかを利用者と相談しながら具体化するその他の案件。

最初の稼働案件は、公開済みの[めしルーレット](https://revise-sato.github.io/meshi-roulette/)を既存物から継続的にブラッシュアップすることとする。作り直しを前提にせず、最初に公開画面とソースを読み、現状を再現してから改善する。

## 役割

- 携帯・PCのChatGPT/Codex画面: 指示、承認、結果確認の操作盤。
- Google Drive `AI-Workspace`: 複数プロジェクトに共通するルールやテンプレートのアイデア、所属先未定の一時受付、取得原本、共有資料・成果物の正本。
- ChatGPT Work Cloud: 調査、監視、定期実行を行う。
- Codex cloud: GitHubリポジトリからコードを取得し、実装、自己診断、テストを行う。
- GitHub `Mitsuru-sato37/ai-workspace-foundation`: コード、設定、テスト、変更履歴の正本。
- ローカルPC: 必要なときに閲覧・編集する複製。常駐処理は持たせない。

## GitHubとGoogle Driveの記録分担

GitHubとGoogle Driveは自動同期される一つの保管庫ではなく、用途別の正本である。foundationプロジェクトのDrive自動連携は無効で、Drive上の変更がGitHubへ自動記録される前提を置かない。

| 記録・成果物 | 正本 | GitHubに残すもの |
| --- | --- | --- |
| コード、設定、テスト、実装上の決定、再現・引き継ぎ手順 | GitHub | ファイル本体と変更履歴 |
| プロジェクト固有のアイデアメモ | 対象GitHubリポジトリの `docs/ideas/` | Markdown本文と変更履歴 |
| 共通事項のアイデア、所属先未定の一時メモ | Google Drive `AI-Workspace/00_Inbox` | 共通ルールと受付・移動手順 |
| 調査資料、取得原本、共有・完成成果物 | Google Drive | 資料本文は複製せず、必要な作業記録から文書名・URL・更新日・概要を参照 |
| 保存先の決め方、命名規則、保存・引き継ぎ手順 | GitHubの運用文書 | ルールと再現可能な手順を管理 |
| 作業の経過、判断、検証結果、次の手順 | 対象リポジトリの `docs/STATUS.md` またはそこから参照される記録 | 何を、なぜ行い、何を確認し、どのDrive資料を読んだ/更新したか、次に何をするかを記録 |

プロジェクト固有のアイデアは、そのプロジェクトのコードや仕様と同じ変更履歴で扱えるようGitHubリポジトリへ保存する。複数プロジェクトに共通するアイデアと所属先未定の一時メモは `AI-Workspace/00_Inbox` に保存し、所属先が決まったら移す。調査資料、取得原本、共有・完成成果物は用途に合うDrive領域を正本とし、リポジトリからリンクする。Drive資料本文をGitHubへ重複保存せず、認証情報や個人情報も保存しない。

GitHubとDriveの接続状況は、それぞれのコネクタが対象リポジトリ/フォルダを実際に読み書きできるか個別に確認する。片方が見えることを他方との同期成功の証拠にしない。

## Google Drive構成

```text
AI-Workspace/
├── 00_Inbox/       共通事項のアイデアと、所属先未定の一時受付
└── 01_運用ルール/  AI共通のファイル管理ルール
```

プロジェクトの資料は、既存のプロジェクト別Driveフォルダを使う。汎用フォルダを重ねて作らず、保存先の正本を案件ごとに確認する。

## 情報の流れ

1. 新しい思いつきは範囲を判定して正本へ保存する。プロジェクト固有ならそのリポジトリの `docs/ideas/`、共通事項または所属先未定なら `00_Inbox` に入れる。思いつきは実行を約束しない。
2. 利用者が実行を望んだアイデアは `docs/11_idea_intake.md` で担当を判定し、資料や成果物は用途に合う既存のDriveフォルダを正本として使う。
3. 実装とテストはCodex cloudのリポジトリ環境で実行し、GitHubへ履歴を残す。
4. 調査・監視・定期実行はChatGPT Work Cloudに置き、Google DriveとGitHubの接続先から必要な情報を読む。
5. 共有する成果物は用途に合う既存のGoogle Driveフォルダへ保存する。旧版の保管場所はプロジェクトごとの既存構成に従う。

## クラウド移行の完了判定

Codex cloud環境で`uv sync`、`uv run project doctor`、`uv run pytest`を実行し、対象リポジトリ・設定値・テスト件数を確認する。別途、ChatGPT Work Cloudのタスクを携帯から開始または確認し、PC停止中でも継続することを確かめる。設定文書だけの変更は移行完了に含めない。

## 採用しない構成

Obsidianは現時点の中心にはしない。Markdown編集には強いが、Google Driveと併用するとメモの正本が二つになり、携帯・PC間の共有経路が増えるため。必要になった時点で閲覧・編集用として再検討する。
